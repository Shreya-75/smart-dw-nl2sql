Problem Statement

Organizations store large volumes of structured data in data warehouses, but accessing insights from this data often requires knowledge of SQL and deep technical expertise. Business users — analysts, managers, and executives — face significant delays in decision-making because they depend on technical teams to write and run queries.

Core Problem
The gap between business intent (a question in plain English) and data retrieval (a SQL query) creates organizational inefficiency, slow feedback loops, and misaligned priorities between business and IT.

This project solves that by building a Smart Data Warehouse integrated with an Agentic NL2SQL system. The system uses Large Language Models and a five-agent pipeline to:

  • Understand a user's natural language question
  • Generate a syntactically and semantically correct SQL query
  • Validate the query for safety and correctness before execution
  • Execute it against a star-schema MySQL data warehouse
  • Return results with auto-generated visualizations and business insights

Dataset: Olist Brazilian E-Commerce

The Olist dataset is a real-world, multi-table e-commerce dataset with 100,000+ orders placed on the Brazilian marketplace between 2016 and 2018. It covers the full order lifecycle — purchase, payment, shipping, delivery, and customer review.

System Architecture

The system is composed of five tightly integrated layers, each with a single well-defined responsibility. Data flows top-down from the user interface through the AI layer, into the execution engine, down to the data warehouse, which was populated by the ETL pipeline.

🌐 Layer 5 — User Interface (Streamlit Web App + Power BI)
Natural language input → charts, tables, AI insights
↕
🤖 Layer 4 — Agentic AI Layer (5-Agent LLM Pipeline)
Query Understanding → NL2SQL → Validation → Execution → Insights
↕
⚙️ Layer 3 — Execution & Validation Layer
SQL safety checks · query runner · result formatter
↕
🗄️ Layer 2 — Data Warehouse (Star Schema — MySQL 8.0)
fact_sales · dim_customers · dim_products · dim_sellers · dim_time
↕
🔧 Layer 1 — Data Pipeline (ETL — Python / Pandas / SQLAlchemy)
Ingest → Clean → Transform → Feature Engineer → Load
Why this architecture is strong
Each layer is independently testable and replaceable. The ETL layer can be swapped for Apache Airflow. The LLM backend can switch between GPT-4o and Llama 3 without touching the UI. The data warehouse can scale from MySQL to BigQuery/Redshift.

ETL Pipeline Overview

The ETL pipeline transforms nine raw Olist CSV files into a clean, analytics-optimized star-schema data warehouse. It runs as a sequence of Python scripts orchestrated by a single entry-point run_etl.py.

Extract

Load all 9 CSV files into Pandas DataFrames. Profile each file: row counts, null percentages, data types, value distributions.

Transform

Clean nulls, deduplicate, normalize strings, parse timestamps, translate categories, engineer derived features (delivery_time, delay, etc.).

Load

Write cleaned DataFrames into MySQL dimension tables first (referential integrity), then the fact table. Use batch inserts for performance.

    "orders":       "olist_orders_dataset.csv",

    "payments":     "olist_order_payments_dataset.csv",
    "reviews":      "olist_order_reviews_dataset.csv",
    "products":     "olist_products_dataset.csv",
    "sellers":      "olist_sellers_dataset.csv",
    "geolocation":  "olist_geolocation_dataset.csv",

def load_all() -> dict[str, pd.DataFrame]:
    dfs = {}
    for name, filename in FILES.items():
        path = RAW_DIR / filename
        df = pd.read_csv(path, low_memory=False)
        logger.info(f"Loaded {name}: {df.shape[0]:,} rows × {df.shape[1]} cols")
        dfs[name] = df
    return dfs

def profile(dfs: dict[str, pd.DataFrame]) -> None:
    for name, df in dfs.items():
        null_pct = (df.isnull().sum() / len(df) * 100).round(2)
        logger.info(f"\n── {name} ──\n{null_pct[null_pct > 0].to_string()}")

if __name__ == "__main__":
    dfs = load_all()
    profile(dfs)

Null Handling Strategy (per dataset)

import pandas as pd
import numpy as np
from loguru import logger

DATETIME_COLS = {
    "orders": [
        "order_purchase_timestamp",
        "order_approved_at",
        "order_delivered_carrier_date",
        "order_delivered_customer_date",
        "order_estimated_delivery_date",
    ],
    "reviews": ["review_creation_date", "review_answer_timestamp"],
    "order_items": ["shipping_limit_date"],
}

def clean_orders(df: pd.DataFrame) -> pd.DataFrame:
    df = df.drop_duplicates(subset=["order_id"])
    for col in DATETIME_COLS["orders"]:
        df[col] = pd.to_datetime(df[col], errors="coerce")
    df["order_status"] = df["order_status"].str.strip().str.lower()
    logger.info(f"Orders cleaned: {len(df):,} rows")
    return df

def clean_customers(df: pd.DataFrame) -> pd.DataFrame:
    df = df.drop_duplicates(subset=["customer_id"])
    df["customer_city"] = df["customer_city"].str.strip().str.lower()
    df["customer_state"] = df["customer_state"].str.strip().str.upper()
    return df

def clean_products(df: pd.DataFrame, translation: pd.DataFrame) -> pd.DataFrame:
    df = df.drop_duplicates(subset=["product_id"])
    df = df.merge(translation, on="product_category_name", how="left")
    df["product_category_name_english"].fillna("unknown", inplace=True)
    df["product_category_name"].fillna("unknown", inplace=True)
    num_cols = ["product_weight_g","product_length_cm","product_height_cm","product_width_cm"]
    for col in num_cols:
        df[col].fillna(df[col].median(), inplace=True)
    return df

def clean_reviews(df: pd.DataFrame) -> pd.DataFrame:
    df = df.drop_duplicates(subset=["review_id"])
    df["review_comment_message"].fillna("", inplace=True)
    df["review_comment_title"].fillna("", inplace=True)
    for col in DATETIME_COLS["reviews"]:
        df[col] = pd.to_datetime(df[col], errors="coerce")
    return df

def clean_sellers(df: pd.DataFrame) -> pd.DataFrame:
    df = df.drop_duplicates(subset=["seller_id"])
    df["seller_city"] = df["seller_city"].str.strip().str.lower()
    df["seller_state"] = df["seller_state"].str.strip().str.upper()
    return df

def clean_all(dfs: dict) -> dict:
    dfs["orders"]    = clean_orders(dfs["orders"])
    dfs["customers"] = clean_customers(dfs["customers"])
    dfs["products"]  = clean_products(dfs["products"], dfs["translation"])
    dfs["reviews"]   = clean_reviews(dfs["reviews"])
    dfs["sellers"]   = clean_sellers(dfs["sellers"])
    return dfs

Step 3 — Feature Engineering

File: etl/feature_engineering.py

Derived ColumnFormulaBusiness Meaning
delivery_time_daysdelivered_customer_date − purchase_timestampTotal days from order to receipt
delay_daysdelivered_customer_date − estimated_delivery_datePositive = late; negative = early
is_latedelay_days > 0Boolean flag for SLA breach
total_order_valueSUM(price + freight_value) per orderGross order value
approval_time_hoursorder_approved_at − order_purchase_timestamp (hours)Payment processing speed
def engineer_features(orders: pd.DataFrame, items: pd.DataFrame) -> pd.DataFrame:
    merged = orders.copy()

    merged["delivery_time_days"] = (
        (merged["order_delivered_customer_date"] - merged["order_purchase_timestamp"])
        .dt.total_seconds() / 86400
    ).round(2)

    merged["delay_days"] = (
        (merged["order_delivered_customer_date"] - merged["order_estimated_delivery_date"])
        .dt.total_seconds() / 86400
    ).round(2)

    merged["is_late"] = merged["delay_days"].apply(lambda x: 1 if x > 0 else 0)

    merged["approval_time_hours"] = (
        (merged["order_approved_at"] - merged["order_purchase_timestamp"])
        .dt.total_seconds() / 3600
    ).round(2)

    # Aggregate item-level values to order level
    order_totals = items.groupby("order_id").agg(
        total_price=("price", "sum"),
        total_freight=("freight_value", "sum"),
        item_count=("order_item_id", "count")
    ).reset_index()
    order_totals["total_order_value"] = order_totals["total_price"] + order_totals["total_freight"]

    merged = merged.merge(order_totals, on="order_id", how="left")
    return merged

Load Order Matters
Always load dimension tables BEFORE the fact table to satisfy foreign key constraints: dim_time → dim_customers → dim_products → dim_sellers → fact_sales. 
from sqlalchemy import create_engine, text
from loguru import logger
import pandas as pd
import os

def get_engine():
    url = (
        f"mysql+pymysql://{os.getenv('DB_USER')}:{os.getenv('DB_PASSWORD')}"
        f"@{os.getenv('DB_HOST')}:{os.getenv('DB_PORT')}/{os.getenv('DB_NAME')}"
        f"?charset=utf8mb4"
    )
    return create_engine(url, pool_size=5, max_overflow=10)

def load_dim_time(engine, min_date, max_date):
    dates = pd.date_range(min_date, max_date, freq="D")
    dim_time = pd.DataFrame({
        "date_key":  dates.strftime("%Y%m%d").astype(int),
        "full_date": dates.date,
        "day":       dates.day,
        "month":     dates.month,
        "year":      dates.year,
        "quarter":   dates.quarter,
        "day_of_week": dates.day_name(),
        "is_weekend":  dates.dayofweek >= 5,
        "week_of_year": dates.isocalendar().week.values,
    })
    dim_time.to_sql("dim_time", engine, if_exists="replace", index=False, chunksize=1000)
    logger.info(f"dim_time loaded: {len(dim_time):,} rows")

def load_table(df: pd.DataFrame, table: str, engine, chunksize=5000):
    df.to_sql(table, engine, if_exists="replace", index=False, chunksize=chunksize, method="multi")
    logger.info(f"{table} loaded: {len(df):,} rows")

Multi-Agent Architecture

The AI core is a five-agent sequential pipeline. Each agent has a single responsibility, can be tested independently, and passes a structured payload to the next agent. Failures at any step trigger a retry with rephrasing feedback to the upstream LLM.

1
Query Understanding
Parse intent, entities, filters
→
2
NL2SQL
Generate SQL from schema+intent
→
3
Validation
Safety + syntax + schema checks
→
4
Execution
Run on MySQL, return DataFrame
→
5
Insights
Summarize + recommend
Retry Loop
If Agent 3 (Validation) rejects a query, or Agent 4 (Execution) catches a runtime SQL error, the system feeds the error message back to Agent 2 with a correction prompt. Maximum 3 retry attempts before returning a user-friendly failure message.

Converts the user's raw natural language into a structured JSON intent object. This separates intent parsing from SQL generation, making the pipeline more reliable and debuggable.

from openai import OpenAI
import json, os

SYSTEM_PROMPT = """You are a query understanding agent for a data warehouse about Brazilian e-commerce.
Extract structured intent from the user's natural language question.

Return ONLY valid JSON with these fields:
- intent: one of [aggregation, trend, comparison, lookup, ranking]
- metric: the measure to compute (revenue, orders, review_score, delivery_time, etc.)
- dimension: the grouping field (customer_city, customer_state, product_category, seller_id, etc.)
- filters: dict of filter conditions (year, month, quarter, order_status, payment_type, etc.)
- limit: integer or null
- sort_order: "ASC" or "DESC"
- time_grain: one of [daily, monthly, quarterly, annual, null]

Schema tables: fact_sales, dim_customers, dim_products, dim_sellers, dim_time"""

client = OpenAI(api_key=os.getenv("OPENAI_API_KEY"))

def understand_query(user_query: str) -> dict:
    response = client.chat.completions.create(
        model=os.getenv("OPENAI_MODEL", "gpt-4o"),
        messages=[
            {"role": "system", "content": SYSTEM_PROMPT},
            {"role": "user", "content": user_query}
        ],
        response_format={"type": "json_object"},
        temperature=0,

Agent 2 — NL2SQL Generation Agent

File: agents/sql_agent.py

Takes the structured intent from Agent 1 + full schema context → generates a syntactically valid, optimized SQL query. Uses schema-aware prompting to prevent hallucinated table/column names.

SCHEMA_CONTEXT = """
DATABASE SCHEMA:

fact_sales(fact_id, order_id, order_item_id, customer_id, product_id, seller_id,
           date_key, order_status, payment_type, payment_installments, payment_value,
           price, freight_value, total_order_value, review_score,
           delivery_time_days, delay_days, is_late, approval_time_hours)

dim_customers(customer_id PK, customer_unique_id, customer_city, customer_state, customer_zip_code_prefix)

dim_products(product_id PK, product_category_name, product_category_name_english,
             product_weight_g, product_length_cm, product_height_cm, product_width_cm)

dim_sellers(seller_id PK, seller_city, seller_state, seller_zip_code_prefix)

dim_time(date_key PK, full_date, day, month, year, quarter, day_of_week, is_weekend, week_of_year)

JOINS:
- fact_sales.customer_id → dim_customers.customer_id
- fact_sales.product_id  → dim_products.product_id
- fact_sales.seller_id   → dim_sellers.seller_id
- fact_sales.date_key    → dim_time.date_key
"""

SQL_SYSTEM = f"""You are an expert MySQL SQL generator for a star-schema data warehouse.
{SCHEMA_CONTEXT}

Rules:
1. ONLY generate SELECT statements — never INSERT, UPDATE, DELETE, DROP, TRUNCATE, ALTER
2. Always alias aggregates (SUM(...) AS total_revenue)
3. Use explicit JOIN syntax — never implicit comma joins
4. Apply LIMIT only when explicitly asked or when result > 1000 rows is expected
5. Use dim_time.year / dim_time.month / dim_time.quarter for time filtering
6. Return ONLY the SQL query — no explanation, no markdown fences
"""

def generate_sql(intent: dict, user_query: str) -> str:
    user_msg = f"""User question: {user_query}
Parsed intent: {json.dumps(intent, indent=2)}
Generate the MySQL SELECT query:"""

    response = client.chat.completions.create(
        model=os.getenv("OPENAI_MODEL", "gpt-4o"),
        messages=[
            {"role": "system", "content": SQL_SYSTEM},
            {"role": "user", "content": user_msg}
        ],
        temperature=0,
    )
    sql = response.choices[0].message.content.strip()
    sql = sql.replace("```sql", "").replace("```", "").strip()
    return sql

Agent 3 — SQL Validation Agent

File: agents/validation_agent.py

Validation Checks

Safety Check

Reject any query containing DELETE, DROP, UPDATE, INSERT, TRUNCATE, ALTER, EXEC, GRANT, REVOKE.

Schema Check

Verify all referenced table names and column names exist in the known schema dictionary. Flag unknown identifiers.

Syntax Check

Parse SQL with sqlparse library. Ensure balanced parentheses, valid clause ordering (SELECT → FROM → JOIN → WHERE → GROUP BY → HAVING → ORDER BY → LIMIT).

Complexity Guard

Warn if query has more than 5 JOINs or more than 3 subqueries, which may indicate hallucination or an overly complex generation.

import sqlparse, re
from dataclasses import dataclass

FORBIDDEN = re.compile(
    r"\b(DELETE|DROP|UPDATE|INSERT|TRUNCATE|ALTER|EXEC|GRANT|REVOKE|CREATE|REPLACE)\b",
    re.IGNORECASE
)

KNOWN_TABLES = {"fact_sales","dim_customers","dim_products","dim_sellers","dim_time"}
KNOWN_COLUMNS = {
    "fact_sales": {"fact_id","order_id","order_item_id","customer_id","product_id",
                   "seller_id","date_key","order_status","payment_type","payment_installments",
                   "payment_value","price","freight_value","total_order_value","review_score",
                   "delivery_time_days","delay_days","is_late","approval_time_hours"},
    "dim_customers": {"customer_id","customer_unique_id","customer_city","customer_state","customer_zip_code_prefix"},
    "dim_products": {"product_id","product_category_name","product_category_name_english",
                     "product_weight_g","product_length_cm","product_height_cm","product_width_cm"},
    "dim_sellers": {"seller_id","seller_city","seller_state","seller_zip_code_prefix"},
    "dim_time": {"date_key","full_date","day","month","year","quarter","day_of_week","is_weekend","week_of_year"},
}

@dataclass
class ValidationResult:
    is_valid: bool
    errors: list[str]
    warnings: list[str]

def validate_sql(sql: str) -> ValidationResult:
    errors, warnings = [], []

    if FORBIDDEN.search(sql):
        errors.append(f"Forbidden keyword detected: {FORBIDDEN.search(sql).group()}")

    parsed = sqlparse.parse(sql)
    if not parsed or not sql.strip().upper().startswith("SELECT"):
        errors.append("Query must start with SELECT")

    table_refs = re.findall(r'\b(fact_sales|dim_\w+)\b', sql, re.IGNORECASE)
    for t in set(table_refs):
        if t.lower() not in KNOWN_TABLES:
            errors.append(f"Unknown table: {t}")

    join_count = len(re.findall(r'\bJOIN\b', sql, re.IGNORECASE))
    if join_count > 5:
        warnings.append(f"Complex query with {join_count} JOINs — verify correctness")

    return ValidationResult(is_valid=len(errors) == 0, errors=errors, warnings=warnings)

Agent 4 — Execution Agent

File: agents/execution_agent.py

import pandas as pd
from sqlalchemy import text
from tenacity import retry, stop_after_attempt, wait_exponential
from loguru import logger
import os

@retry(stop=stop_after_attempt(3), wait=wait_exponential(multiplier=1, min=1, max=5))
def execute_query(sql: str, engine) -> pd.DataFrame:
    timeout = int(os.getenv("QUERY_TIMEOUT_SECONDS", 30))
    with engine.connect() as conn:
        conn.execute(text(f"SET SESSION MAX_EXECUTION_TIME={timeout * 1000}"))
        result = conn.execute(text(sql))
        df = pd.DataFrame(result.fetchall(), columns=result.keys())
    logger.info(f"Query returned {len(df):,} rows")
    return df

Responsible AI Practices

SQL Safety Filter

Agent 3 blocks all DDL/DML commands. Queries are read-only by database user grant (SELECT only — no INSERT/UPDATE/DELETE permissions granted to olist_user).

Input Sanitization

User input is never directly interpolated into SQL strings. LLM output is validated before execution. Max input length: 500 characters.

Query Logging

Every interaction is logged: timestamp, user query, generated SQL, validation result, execution time, row count, insight generated. Stored in logs/query_log.jsonl.

Explainability

The UI always shows the generated SQL query in an expandable panel, the agent trace (intent → SQL → validation), and confidence indicators.

Graceful Errors

Every failure mode returns a user-friendly message. No stack traces exposed to users. 3 retry attempts with progressive rephrasing before final fallback.

Rate Limiting

OpenAI API calls are wrapped with exponential backoff (tenacity). Maximum 10 queries per minute per session to control costs.

from loguru import logger
import json
from datetime import datetime
from pathlib import Path

LOG_DIR = Path("logs")
LOG_DIR.mkdir(exist_ok=True)

logger.add(LOG_DIR / "app_{time:YYYY-MM-DD}.log", rotation="1 day", retention="30 days", level="INFO")

def log_query_event(user_query, intent, sql, validation, rows, insight, duration_ms):
    event = {
        "timestamp": datetime.utcnow().isoformat(),
        "user_query": user_query,
        "intent": intent,
        "sql": sql,
        "validation_passed": validation.is_valid,
        "row_count": rows,
        "duration_ms": duration_ms,
        "insight_summary": insight.get("summary", "")
    }
    with open(LOG_DIR / "query_log.jsonl", "a") as f:
        f.write(json.dumps(event) + "\n")
    logger.info(f"Query completed in {duration_ms}ms | rows={rows}")
